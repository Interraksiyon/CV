Datamancer (Optimization & UX Focus)

Role: Sole Programmer, UI/UX Designer | Tech: Löve2D, Lua
  • Overview: A heavy text-based simulation that required managing continuous streams of data and lists.
  • Technical Challenges: Rendering non-stop text caused major performance drops and made the UX very tiring for the player. Additionally, constantly pulling random text from lists while scenes played out was logically complex.
  • Solutions: Solved the performance problem by separating the visuals from the logic. Instead of drawing everything, I built a mathematical simulation that processed lists and workflows in the background without rendering them. I also redesigned the UI panels to make the data much easier to read and understand.

3 Bug Bullet (Procedural Animation)

Role: Lead Programmer, UX Designer | Tech: Löve2D, Lua
  • Overview: An action prototype that needed dynamic, organic enemy movements.
  • Technical Challenges: Standard animations were not enough for the bug-like movements I wanted, requiring dynamic procedural animation.
  • Solutions: I learned and implemented Inverse Kinematics (IK) for the enemies from scratch. I had previously used IK within Godot, but building it from scratch in Löve2D (using AI as a learning and problem-solving partner) helped me deeply understand the technical differences between using a full game engine and a code-based framework.

Project Delivery (Physics & Game Feel)

Role: Lead Developer | Tech: Unity, C#
  • Overview: A liminal cargo delivery game centered around truck driving. The goal was to build a strong atmosphere combined with satisfying driving mechanics.
  • Technical Challenges: Pure physics simulations are often not fun for players and cost a lot of performance. I needed to gamify the simulation so the truck felt realistic and heavy without using overly complex real world physics math.
  • Solutions: I built a semi-physics-based vehicle controller. Instead of pure simulation, I used math tricks, visual feedback, and sensory tweaks to create "fake" physics. This made the truck feel heavy and realistic to the player while keeping the code highly optimized and the gameplay actually fun.

PikiPop (Enemy AI & Tech Art)

Role: Sole Developer | Tech: Godot, GDScript
  • Overview: A roguelike dungeon delving game inspired by classic "Bubble Trouble". I also used this project to learn what Technical Art is by writing my own visual shaders from scratch.
  • Technical Challenges: At first, the bubble enemies just bounced around the screen randomly using basic physics. It did not feel like a real game, and the enemies lacked intelligence or purpose.
  • Solutions: I wrote conditional behaviors and a state machine for the enemies. I programmed them to act differently based on their size and the specific monster inside the bubble. For example, some enemies now pause in mid-air, calculate the player's position, and dash directly at them. If they miss, they enter a "rage" state and trigger a rapid attack sequence. This changed them from random bouncing objects into smart, challenging enemies with meaningful pathfinding.
